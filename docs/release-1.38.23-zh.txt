SPT Assistant 1.38.23 / 热更新宿主 1.5.0

热更新暂停窗口
- 宿主显示“正在热更新 · 游戏已暂停”。窗口至少重绘两次后才开始释放旧模块；模块卸载期间窗口由宿主继续刷新。
- 文件变化检查、模块读取、SHA256 校验、程序集准备和语言资源预热在后台进行；原功能在准备期间继续运行。
- 切换前等待正在进行的原生库存事务、战局仓库保存及制作请求完成；等待过程不会同步阻塞游戏线程。
- 设置文件保存和回退模块写入放到后台。必须接触 Unity/Harmony 的初始化、清理和逐方法撤销补丁留在主线程，每帧执行一个步骤。
- 切换期间暂停 Unity 时间与音频，补偿本地战局基于现实时间的开始时间及截止时间。完成后恢复原时间倍率、音频暂停、鼠标和后台运行设置。
- 候选文件损坏时保留旧模块。部分初始化失败时清理候选模块，恢复上一版本并记录错误；恢复失败则保留提示，允许用户关闭提示或重启游戏。
- 热更新不再在模块卸载时同步等待藏身处制作或战局仓库网络响应。战局仓库在新宿主下会先排空保存事务。
- 这能减少长时间连续占用主线程，不能保证每个不可拆分的原生调用都很短，也不能保证 Windows 永远不会显示“无响应”。状态文件记录步骤数量和最慢步骤，实际游戏内体验仍需验收。

藏身处制作秒完成
- 入口仍为“数据 → 角色管理 → 藏身处”，可开启自动秒完成或点击“完成当前制作”。
- 服务端同时补齐普通制作的 Progress 与 AvailableForFinish；旧版已经推进到满进度、但缺少可领取标志的制作也会修复。
- 客户端收到结果后，在当前原生制作控制器更新时同步 ProductionData；即使角色数据里的进度已经相同，也更新实际运行中的制作控制器。
- 校验角色 ID、是否处于战局、制作开始时间、进行中/中断状态和配方时长，拒绝把旧响应应用到切换角色或重新开始的制作。
- 保留材料消耗、工具、产物及原始制作时间戳；不自动领取或重复生成产物。仍排除连续生产、BTC、水收集器、Scav 宝箱及邪教圈。

本机部署
- 服务端 LocalGearAdmin.module 已热更新，并通过只读 craftStatus 确认普通制作带有可领取状态。
- 宿主 DLL 已加载到当前游戏进程，不能在进程内升级自身。新宿主及核心模块放在游戏目录 mod-updates/assistant-1.38.23。
- 隐藏安装器等待 EscapeFromTarkov 正常退出；不关闭或自动重启游戏。退出后校验哈希、备份旧文件并安装，完成状态写入该目录 install-status.json。
- 正常退出客户端后等待约 3 秒再启动。若安装失败，状态文件会记录原因，可在退出游戏后重新运行包内 InstallHostUpgrade.ps1。

验证
- 新旧客户端及宿主均构建通过；客户端保留两条原有可空引用警告，宿主零警告。
- 90 组 Probe、16 组服务端检查通过，含满进度可领取状态修复、重复执行无额外产物以及制作实例隔离。
- 5 组宿主流程检查通过：后台准备、分帧动作、事务等待、部分初始化失败回退、损坏候选保留旧模块、暂停状态恢复及战局截止时间补偿；原生边界使用测试替身。
- 安装器在隔离目录通过正常安装/备份及损坏包拒绝检查。
- 窗口可见性、真实原生步骤峰值、游戏暂停范围和制作实际领取尚待用户在重启后验收。详见 validation-1.38.23.json。
