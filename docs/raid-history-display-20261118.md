# 历史战局列表未显示修复

## 现象与原因

玩家反馈历史战局页显示“暂无战局记录”。实际 SQLite 已保存一场海岸线成功撤离记录，开局装备、带出物品和 7 条击杀均存在，认证后的列表与详情接口正常返回。

只读客户端诊断确认：`Singleton<TarkovApplication>.Instance` 和 `Singleton<AbstractApplication>.Instance` 均为空，但场景内的 `TarkovApplication`、后端角色和菜单角色均已就绪。旧列表仅从两个单例入口获取身份，提前返回，因而没有发出任何列表请求；空列表绘制又无条件显示“暂无战局记录”。

## 改动

- 缓存实际场景中的应用对象；单例入口为空时每两秒最多查找一次。优先使用后端角色，后端尚未提供角色时使用菜单任务控制器中的就绪角色。
- 尚未就绪、请求中、请求失败和成功读取到空列表分别显示对应状态。只有服务端成功返回空列表后才显示“暂无战局记录”。
- 历史请求设置 30 秒超时，失败后 3 秒重试。刷新失败保留最后一次成功读取的列表。角色切换立即清除旧列表，丢弃上个角色的延迟响应。
- 增加只读 `raid-history-state` 和 `raid-history-check` 诊断；后者执行页面正常读取流程，不修改角色和数据库，不改变战局状态。

## 验证

`dotnet run --project raid-history-tests/Tests.csproj -c Release` 包含生产客户端列表代码。覆盖两个单例均为空而场景角色已就绪、延迟加载、真实接口字段格式、实际绘制的地图/状态/击杀文本、失败提示、刷新保留、角色切换和延迟响应隔离，以及既有 SQLite、装备、击杀和计时器检查。

客户端构建并在战局外热加载后，通过只读 `raid-history-check` 使用游戏自身的 HTTP 客户端验证实际读取。游戏画面的视觉确认仍由用户完成。此次不迁移或重写历史数据库。
