# 奔跑切换物品的镜头问题排查记录

环境：Win11-GPU，EFT 48558 / SPT 5.0。本次用户确认：奔跑互切量子剑和枪时一瞬间剧烈抖动，原版物品互切也出现问题。

## 当前发布：像素物品 1.3.5

删除 `atm-swords-client/HandsLifecycle.cs` 中对原生 `ProceduralWeaponAnimation.InitTransforms` 的全局后置补丁及 `HandsInitialized` 方法。原补丁未限定自定义物品，会在所有本地手持骨架绑定期间执行 `ResetSpring()`、`ResetCameraRotation()` 和 `Sprint` 赋值。本次移除该干预，让原生流程负责收起、拔出和相机状态。

量子剑一直复用原版近战预制体及动画，模型工厂只替换剑的网格和材质。本次没有新增动画，保留非奔跑/待机时的剑格挡、平板展示和收起前姿势清理，也保留自定义物品的无熟练度处理。

验证：编译 0 警告 / 0 错误；46 项剑规则和 38 项物品/终端/程序集检查通过。新增检查断言剑模块不再引用 ProceduralWeaponAnimation 的镜头处理方法。九个模型工厂方法及异步观察身份判断的 IL 与运行中的 1.3.4 版本一致，73 个模型、贴图及许可资源与该版哈希一致。

已发布 `atm-swords` 1.3.5 / `r20261115095845-c6485920`，74 个文件清单 SHA-256 全部通过；当前游戏进程 23072 的宿主状态为第 2 代、`running`、无加载错误、无需重启。服务器与 ProjectE 没有更新或重启。**用户随后实测反馈“仍然猛抖”，1.3.5 也不能视为问题已解决。** 保持全局重置移除，继续查明剩余原因。

## 已否决的补偿尝试

独立实验模块 `sprint-camera` 1.0.0 在奔跑切换后的短暂窗口平滑手部骨架相机，1.0.1 又增加了第一人称最终相机的过渡平滑。用户分别反馈“还是抖”“没有改善或更严重”。两个方案均没有通过视觉验收，不能作为可用修复发布。

已把该模块清单设为 `enabled=false` 并请求卸载，当前宿主确认 `disabled`、`ready=false`、无卸载错误。不要重新启用这些实验版本。源码实验目录和历史发布包仅作为排查记录保留，不属于当前有效修复。

1.0.1 诊断记录过 2 次切换通知、161 次骨架过滤、162 次最终相机过滤，无捕获异常，过滤前角度差峰值约 179°。这只能说明实验代码有执行，不能证明抖动根因，也不能证明塔科夫原版有 BUG。尚未完成无模组对照。

已加载只读 `camera-trace` 1.0.0。它不打补丁、不写相机状态，在最终主相机 onPreCull 回调记录实际位置、旋转、FOV、玩家视角、骨架相机和手持动画状态。检测切换后收集 1.5 秒再一次性写入 `state/camera-trace/data/camera-trace.json` 并停止采样。不得把该观察模块描述为修复。

后续视觉验证由用户在战局中执行。继续查找原生动画状态交接及其他模组的实际调用，不继续叠加未经证实的镜头补偿。

## 只读采样定位：VisualPass 被换手状态错误拦截

用户完成采样后，记录显示实际是 M4A1 (`5447a9cd4bdc2dbd208b4567`) 到原版斧头 (`5c0126f40db834002a125382`) 的奔跑切换，600 帧、约 4.78 秒。FOV 全程 40，玩家视角输入恒定；相机在拔出第一帧附近发生约 17.38° 的单帧旋转。枪械收起阶段，旧 Camera_animated 的世界位置停止跟随，而玩家继续移动。问题并不限于自定义物品。

同时辅助模块日志反复记录 `Visual lifecycle guard: disposed hands controller awaiting replacement`，只读诊断累计跳过 2646 次。源码 `esp-cover/PlayerVisualGuard.cs` 的 `Ready` 在 `HandsController.Destroyed` 为真时跳过整个原生 `Player.VisualPass`；娱乐模块的视觉前置钩子也复用该判断。原生 VisualPass 包括 ProcessEffectors、武器根节点、头部及 LateTransformations 更新，不能因换手中旧控制器被释放就一并停止。

本次删除该换手条件，保留人物已销毁、缺少 MovementContext、缺少 PlayerBones，以及菜单/第三人称缺少相机的保护。镜头重置和平滑实验保持停用，原生动画和镜头流程继续负责正常切换。

构建通过（0 错误，另两项既有可空性警告位于 EventLoadCode 和 EventRaidDiagnostics）。`probe --visual-lifecycle-only` 通过，包括编译后的 Ready 不再访问 HandsController、仍保留人物/移动/骨架保护及集成生命周期检查。完整 probe 在无关的趣味功能菜单路由断言失败，没有把完整测试报告成通过；未修改该菜单断言。

已发布辅助核心 SHA-256 `0EA5236FE9B2C3E183E6D04E89DF5E9C315EB9599107C6D82C7D3F4CCFC9D184`，旧核心备份于 `mod-backups/sprint-visualpass-20261115-100924911`。当前游戏进程的热加载宿主确认第 2 代、`ready=true`、无错误、哈希匹配。

**用户战局验收：本次修改后明确反馈“终于好了”。** 本次根因是辅助 MOD 在正常手部控制器过渡期间错误阻断整个人物视觉更新，不是自定义剑另写了一套错误动画，也不需要用镜头平滑去掩盖。只读采样模块随后停用；先前两版镜头平滑实验继续停用。未用事后第二份采样替代用户反馈，也不宣称已经覆盖所有武器组合或场景。
