# 2.4 — 修复线上交易点击上架后卡死（2026-11-27）

多物品上架改动加入了父子容器检查，但旧循环只在 `CurrentAddress.Container.ParentItem` 为 null 时结束。EFT 48558 的库存根节点本来就持有指向 `ItemController` 的地址，而该控制器的 `ParentItem` 返回同一个根节点。这会让普通物品的祖先遍历在根节点上无限循环，阻塞 Unity 主线程，报价请求尚未发送就卡死；单件上架也会触发。

修复后检查到 `ItemController` 所有权边界即结束，不再读取根节点的“父物品”。同时记录已访问 ID，遇到异常循环或超过 64 层嵌套时返回明确错误，保留重复选择和容器/内部物品同时上架的拒绝逻辑。提交前失败会记录诊断日志。

依据：客户端日志停止于点击上架附近，未记录新交易请求。使用既有逆向工具对照原生 `ItemController` 构造函数（给 RootItem 设置 CurrentAddress）、`CreateItemAddress`（构造 ProtectedOwnerItself）及 `get_ParentItem`（返回 RootItem）确认根节点语义。无法获取当前进程转储（系统返回拒绝访问），因此没有声称取得运行中的线程栈。

验证：11 项回归覆盖单件、多件、所有权根节点、自引用根节点、无父节点、重复选择、父子混选、异常自环/多节点环及过深嵌套；测试限制父级读取次数，回归时直接失败而不会挂住测试。客户端 Release 构建通过，0 错误、5 项既有警告。

修复核心已备份后覆盖安装。已经进入旧死循环的客户端无法执行热更新，需要重启客户端后验证；服务端无需重启。游戏内由用户复查背包单件、同类多件和搜刮容器上架，确认不再冻结、成功后物品移除与邮件到账正常。
