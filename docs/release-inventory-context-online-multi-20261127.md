# 2.4 — 库存右键同步、原生菜单与线上交易多选（2026-11-27）

## 更新

- 修复战局内空格右键添加只写入格子、不发送完整库存事件的问题。添加操作现在发送原生 Begin / Succeed 通知，更新搜索已知状态及可见物品格子；不再吞掉添加失败并显示成功。多件添加在提交库存事件之前失败时回滚已执行的操作。
- 空格右键改用 EFT 的 `SimpleContextMenu`、`BaseEmptyContextInteractions` 和动态菜单项，保留目录添加、JSON 添加、剪贴板 JSON 三个入口。使用支持动态操作的原生容器，避免 `EmptyContextInteractions.HasInteractions` 恒为 false 导致菜单不显示。目录和 JSON 编辑窗口仍使用助手界面。原生菜单打开时保留 EventSystem 输入；切换界面、关闭菜单、禁用功能及热更新时释放上下文。
- **物品 → 库存右键菜单**新增三个独立、持久保存的开关：启用右键添加物品、启用右键编辑物品、启用右键设置 FIR。默认均开启；关闭对应开关会隐藏对应入口，不影响其他右键操作。
- **射击 → 投掷物轨迹**中的开关明确命名为“显示投掷物抛物线”，沿用既有配置键与用户已保存的状态。关闭后停止轨迹和落点绘制。
- 战局内线上交易允许在原生新增报价窗口选择同类物品的多件／多组。客户端提交全部选中物品树；服务端按 EFT 原生多选报价结构合计根物品数量，配件与容器内容不计作额外出售数量。保留逐件出售与整包出售的价格语义；确认上架成功后移除全部已选根物品。
- 校验全部上架物品模板、重复 ID、循环、混合模板及数量溢出。FIKA 战局仍沿用现有同步限制。

## 验证范围

- 使用本机 EFT 48558 interop 与 .NET 10 编译客户端和服务端模块。
- 新增 `gear-mail-tests --online-offers`：多堆叠合计、武器树、配件和弹药数量隔离、源数量保持、重复 ID、混合模板、非法数量、数量溢出及循环检测。
- `gear-mail-tests --inventory-json` 运行现有库存与物品树 JSON 回归。
- 原生库存事件顺序对照本机 `ItemController.AddAndRaiseEvents` / `AddResult.RaiseEvents`；多选报价结构对照 SPT `CreateMultiOffer` / `CreatePackOffer`。
- 编译和回归测试不等于游戏画面验收。战局内新增物品的显示、拖动、装备／使用，原生菜单位置与关闭行为，开关即时效果，以及多选报价的实际售出和邮件到账需用户在游戏内检查。

## 游戏内复查建议

1. 在战局背包空格右键添加一件药品或弹药，确认当场可见、可拖动且可按其原生条件使用；再检查容器格子和 JSON 添加。
2. 分别关闭三个库存右键开关，确认只消失对应入口；开关重开与热更新后不出现重复菜单项。
3. 手持投掷物切换显示抛物线，确认线条及落点标记一起停止／恢复。
4. 选择两组同类弹药（例如 30 + 60），确认上架数量为 90、成功后两组均移除；分别检查单价出售和整包出售。
