# 藏身处制作与仪式圈同步修复

- 角色读取只使用已经就绪的菜单任务控制器；处于藏身处时也可使用当前物品界面的任务控制器。不再调用在加载阶段可能抛空引用的 `GetProfileForLocalGame()`。
- 角色尚未就绪时，间隔 2 秒重试；已经返回的同步响应和制作实例快照保留到角色恢复后再校验。不同角色、战局内和制作进程已经替换的结果仍被拒绝。
- 仪式圈异常后的 10 秒重试检查在角色读取之前执行；手动刷新和切换秒完成开关也不能绕过该间隔。未完成的网络请求不会触发每帧角色读取。
- 数据 → 仪式圈新增默认开启的“身处藏身处时可获得仪式圈物品”。在藏身处时，即使预览页面关闭、自动秒完成关闭，也会按 3 秒间隔读取仪式状态，将服务端已经完成的仪式同步到当前原生制作实例。自然完成和手动秒完成共用角色、物品与制作进程校验。
- 只有自动秒完成开关会提前完成仪式；藏身处同步开关本身仅查询状态。奖励通过原生界面手动领取；同步不生成、移动或领取物品。已经进入完成仓储的仪式不再重复应用。

## 验证

客户端目标为 EFT 48558 / .NET 10。构建通过，保留 `EventLoadCode.cs` 与 `EventRaidDiagnostics.cs` 的两条原有 nullable 警告。

```powershell
dotnet build esp-cover/Esp.csproj -c Release -p:NuGetAudit=false
dotnet run --project hideout-sync-tests/Tests.csproj -c Release
dotnet run --project gear-mail-tests/Tests.csproj -c Release
$env:SPT_SOURCE_ROOT=(Get-Location).Path
$env:SPT_GAME_ROOT='D:/SPT-5.0.0-48558'
dotnet run --project probe/Probe.csproj -c Release
```

`hideout-sync-tests` 编译并运行真实的两个控制类，以托管替身模拟 Unity 时间、角色加载、网络响应与原生制作实例，覆盖 7 组用例：未就绪角色、10 秒异常节流、两种同步响应的延后恢复、藏身处自然完成、进行中仪式不加速，以及开关/战局/角色/进程隔离。

完整 Probe 首次在英文格式匹配用例失败，单独重跑全部通过；相关格式词典未修改。服务端规则检查通过，包括仪式圈原生完成标记、重复操作幂等、奖励身份及旧献祭结果拒绝。

这些检查不代表已验证实际游戏中的按钮布局或物品领取。游戏内验收：保持处于藏身处，等待仪式自然完成或点击立即完成；确认无需退出藏身处即可手动领取，领取后物品数量正确，再次刷新不重复发放；登录及角色切换期间不应持续出现这两处同步的空引用日志。
