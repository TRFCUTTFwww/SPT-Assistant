# 暂停报价保留原剩余时间（2026-11-27）

修复原生报价修改窗口将暂停报价的内部防过期截止值识别成永久、显示 -1 的问题。打开窗口时等待服务端报价元数据，明确区分冻结秒数与永久；收到结果后统一重算剩余分钟，不再保留错误的初始 -1。读取失败不会把未知有效期保存成永久。

原生跳蚤列表首次遇到防过期截止值且本地没有报价信息时，会合并发起一次状态读取，不要求先打开 MOD 自定义报价页。读取完成前显示读取状态，随后按原冻结秒数显示“已暂停 HH:mm:ss”。后台读取遵循报价状态版本，编辑、删除后不会写回旧响应。MOD 报价列表与编辑器使用相同的剩余时间规则，冻结秒数优先于永久标记。

例如剩余 17 分钟时暂停，列表固定显示“已暂停 00:17:00”，修改窗口显示 17；关闭暂停并保存后从冻结时长继续倒计时。只有真正永久且没有冻结秒数的报价显示 -1。秒数没有取整写回，编辑分钟数未改变时继续由现有 preserveExpiry 路径保留准确有效期。
