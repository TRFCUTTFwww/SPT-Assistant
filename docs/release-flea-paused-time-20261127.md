# 暂停报价保留原剩余时间（2026-11-27）

修复暂停报价在原生跳蚤市场、购买弹窗及修改窗口中被识别或展示为永久（`9999-12-31` / 超长天数 / `-1`）的问题：

1. **服务端返回真实冻结时长而非永久截止值**：服务端报价池内部继续保留防过期保护，但在原生跳蚤查询（`GetOffers` / `GetOfferByInternalId`）与 MOD 报价状态接口中统一按 `当前时间 + 冻结秒数` 返回到期时间，暂停报价不再向客户端暴露 `PermanentEndTime`。
2. **修复客户端 `UTC+8` 时区偏移导致的截止时间误判**：`NativeExpiry` 改为直接基于 `offer.EndTime - EFT.DateTimeExtensions.UtcNow` 计算剩余秒数，避免 `Unspecified` 时间在本地时区转换时被减去 8 小时（导致永久哨兵值漏判及普通市场报价分钟数归零）。
3. **原生列表实时刷新与逐帧锁定暂停计时**：首次打开原生跳蚤列表自动拉取报价状态，响应到达当帧立即刷新当前可见 `OfferView` 行，不再受原生超长 `_updateTime` 节流影响；已暂停报价逐帧固定显示 `已暂停 HH:mm:ss`，不会倒计时跳秒。
4. **禁止暂停状态被静默转为永久**：编辑器开启“暂停剩余时间”时若分钟数为负数会自动重置为常规正数时长，服务端与客户端保存时均明确拒绝“开启暂停 + 负数永久分钟”的冲突组合，不再静默丢弃暂停标记变成永久报价。

验证：客户端与服务端管理模块 Release 编译通过；本地化检查（`probe --localization-only`）、自定义报价回归与双进程 SQLite 冷恢复测试全部通过。游戏内实际界面表现由用户进一步确认。
