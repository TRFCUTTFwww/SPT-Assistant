# 跳蚤持久化与开发工具输入

基于 a2f9e4b 后续开发，2026-11-26。本说明更新同日下拉选择版本的交互和有效期行为。

## 交互与后台同步

- 跳蚤市场使用「物品列表」「市场规则」「跳蚤方案」「自定义报价」四个页面按钮。
- JSON 格式化、复制、粘贴、刷新、导入导出、增删节点，以及任务和枪械预设操作恢复直接按钮，并根据可用宽度换行。
- 组件定位、物品选择、商人和任务状态筛选继续使用下拉框。
- 自动同步保留 12 秒轮询（在线价格同步过程中为 2 秒），通过独立请求更新状态。轮询不禁用编辑控件，不回填输入草稿；只在报价覆盖或出售权限实际变化时重算筛选结果，并保留原滚动位置。修改或选择操作会使旧的轮询响应失效。
- 只有用户更改搜索／分类／筛选条件才主动回到列表顶部。

## 自定义报价

- 支持玩家名、出售物品、卢布单价、存量、剩余分钟、市场信誉及当前／最大耐久。
- 新报价默认开启「保存到 SQLite」，也可关闭后创建临时报价；现有临时报价可另存为持久化记录。
- 数据库位于服务端 user/mods/LocalGearMail/flea-prices/custom-offers.sqlite，使用本机 SQLite，WAL 日志及 FULL 同步。
- 重启服务端后将未到期、未售罄且未下架的记录重新注册到原生报价池。保留购买后剩余存量和原到期时间，停服期间仍正常计算有限报价的有效期。
- 到期／售罄／下架只停止出售，保留记录；「重新创建」按初始存量和有效期重新上架；「下架并保留」保留设置；「删除报价」二次确认后同时删除原生报价与记录。
- 物品模板缺失的记录显示不可用，保留在数据库中。重复恢复和重新创建不会复制记录或保留两份同一报价。
- 自定义报价绕过原生 AI 同类报价生成数量限制，继续注册原生模板和玩家索引。枪械使用默认配件树并重新分配物品 ID。
- 「供大于求（商人）」与「供大于求（市场）」独立。市场开启时展示并购买的库存为 Int32.MaxValue（2147483647），不扣减原始报价剩余库存。

## 数值与永久有效期

- 通用设置的 Int32／Float32／Float64 输入不再受滑块范围限制，滑块保留便于拖动的区间。
- 物品生成和组件编辑、枪械数值／耐久、物品 JSON、Buff、AI 血量／场景参数、角色／信誉／业力、服务端配置、跳蚤定价／倍率／百分比与自定义报价移除对应的人为上下限。
- 自定义报价原来的 30 天、百万信誉及模板耐久上限已取消；允许超出模板最大耐久、当前耐久高于最大耐久及负数开发值。
- 原生字段类型、有限数值、整数精度、JSON 结构、有效组件、库存容器空间与邮件批次容量检查保留。数值直接交给游戏仍可能由原生代码调整，例如服务端 CommonSkill.Progress 自身会将技能进度限制到 5100；本次没有改写该原生规则。
- 自定义报价剩余分钟：任意负整数均表示永久，SQLite 保存原永久设置，重启恢复及重新创建均保留；0 表示立即到期。
- 保险邮件领取期限（秒）、普通／Unheard 任务奖励邮件领取期限（小时）：负数表示永久，发送时转换为原生可表示的长期截止时间。仅影响之后产生的邮件，服务端配置保存后按原有提示重启生效。
- 玩家与 AI 普通 Buff／单项 Buff／出生 Buff 的负数持续时间表示本次效果永久，可手动移除，角色／战局销毁仍正常清理。
- 命中提示、受击提示、击杀信息、击杀特效、通知、弹道轨迹与每枪微调持续时间的负数表示不按时间过期；关闭功能、清理、数量上限和战局生命周期仍然生效。
- 制作／建造耗时的 -1 表示使用原始设置；时间间隔、时钟格式和结构化索引沿用自身含义，这些字段不是物品有效期。

## 验证范围

- 使用 EFT 48558 互操作程序集执行客户端与服务端 Release 构建。
- 自定义报价测试覆盖原生请求／序列化、放开的开发数值、负数永久、独立市场供大于求、购买扣减和移除。
- 用两个独立进程及新的原生报价池验证 SQLite 冷恢复：剩余库存、绝对到期时间、永久状态、配件、售罄／到期／下架／缺失模板状态、重新创建、临时报价持久化及永久删除。
- 检查保险与任务邮件的永久期限转换，并运行现有服务端管理、AI 难度和客户端 Probe 回归。
- 使用当前已部署的旧 LocalGearMail.dll 独立验证热补丁：物品负数／超模板数值和商人好感范围在不重启服务端时也能放开。
