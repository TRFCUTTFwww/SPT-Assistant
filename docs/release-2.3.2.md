# SPT Assistant 2.3.2

适用 SPT 5.0 BE / EFT 48558。客户端宿主升级到 1.6.0，需要关闭客户端后更新宿主文件；之后的辅助功能模块仍支持热更新。服务端基础模块的改动需要重启服务端。

- 装甲列车修改停站时间后刷新机车和车厢的原生运动插值；立即发车会同步运动时间基准。到站、发车倒计时仍用时／分／秒。
- 行动前时间设置改为地图昼夜时刻 `00:00:00–23:59:59`，每次新战局应用一次，热更新不重复应用。旧的下局撤离时长设置不再覆盖地图撤离时间。
- 人物加入全身枪弹跳弹开关，未穿护甲的部位也适用；使用碰撞体原生跳弹判断，并阻止极端弹道情况下的本地枪弹伤害。爆炸、近战和环境伤害不受此开关影响。
- 交互能力将破门强开与门卡破解按一致卡片排列。外交豁免的 AI 判断缓存到战局角色列表，避免每次目标查询扫描角色。
- 设置新增日志与诊断：ALL、TRACE、DEBUG、INFO、WARNING、ERROR、FATAL、OFF；支持 ZIP 导出，可选硬件、性能、SPT 服务端与游戏日志，常见令牌和密码会脱敏。
- 性能附件包含帧时间、P99、慢帧、辅助功能 CPU 耗时、GC 统计和可选功能分段。不能据此直接归因其他 Mod 或 GPU 内部耗时。物理警告调用栈采集改为默认关闭。
- 服务端仅过滤聊天轮询的普通请求日志，保留警告、异常和错误；没有其他聊天成员时降低客户端轮询频率。
- 加入独立调试侧栏和默认关闭的总开关。空引用、数组越界以及受控的堆栈溢出、内存访问和热更新失败模拟可展示错误保护界面；模拟不会结束真实战局。
- 可捕获的运行时错误显示半透明主题色全屏 `:(` 界面，提供日志导出、关闭和重启。战局内会先保留装备与背包快照，尝试写入 SQLite 救援备份，再请求原生幸存结算；等待保存时暂不允许直接重启。
- 热更新加载或初始化失败后保持暂停，允许手动回退上一正常版本或等待新模块。回退预检在后台执行；若旧模块清理失败则阻止继续切换，要求重启。
- 原生崩溃导致游戏进程退出时，由独立提示程序显示已知异常或退出码，并允许导出日志和重启。进程已退出后无法执行游戏内结算；不能保证原生崩溃后存档已保存，也不能承诺任意错误后都能稳定回退。
- 趣味物品关闭时不注册模板、商人或构造相关服务。已有物品树在载入前备份并暂存到存档扩展字段，重新启用后通过邮件返还仍受支持的物品。完整原始备份保留于服务端 `LocalGearMail/backups/fun-items`。

新增命令：`/logs export`、`/logs level INFO`、`/debug on|off|null|bounds|stack|access|reload`、`/nexttime HH:MM:SS|off`、`/ricochet on|off`。原有 `/train` 命令同步使用列车修正。

离线与隔离服务端检查不代表已在实际战局完成视觉、发车、跳弹或帧率验证。客户端未运行时，安装成功只表示文件已更新，宿主与功能模块在下次启动时加载。
