# 2.4 — 快速热更新初始化顺序修复（2026-11-27）

最新热更新提速版本在收集第一批初始化动作时，会提前枚举 `plugin.LoadSteps()`，而创建 `plugin` 的动作尚未执行。因此首次加载在两个宿主步骤后抛出空引用，模块进入暂停状态。

将批处理抽为共享的 `LifecycleSteps.Batch`：先执行当前动作，再枚举下一动作，保留每批多步骤执行与异常向宿主传播的行为。初始化迭代器可以安全依赖此前动作建立的状态。

同时将持久化 Hook 路由器的创建提前到 Plugin 实例构造时：`PlayerVisualGuard` 早于普通功能加载，必须在它安装保护 Hook 前提供路由器，不能等待 `LoadSteps` 中的配置初始化步骤。

验证：客户端 Release 构建通过；新增生命周期测试覆盖批大小 1、2、20、依赖初始化、尾批、迭代器释放与失败后停止枚举；完整宿主测试（包括快速模式、失败暂停和回滚）及 `--hook-router` 测试通过。游戏界面验证由用户进行。

本机覆盖安装后，宿主 1.7.0 成功加载核心 2.4，恢复为 `ready=true`。再次请求热更新，generation 从 1 升至 2，日志记录耗时 483.6 ms，复用全部 258 个 Hook、未创建新 Hook；状态无错误、无回滚、未暂停。安装文件与构建产物的 SHA-256 一致。
