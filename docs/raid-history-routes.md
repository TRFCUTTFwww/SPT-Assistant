# 历史战局：转移路线与装备折叠

历史战局 → 查看详情新增“转移路线”页签。服务端保存开局请求／响应中的经过地图列表，保留重复访问；结算时保存原生转移目的地。目的地单独标明为结算请求中的目标，不能把请求转移当作已经到达。

旧 SQLite 记录兼容读取。没有保存路线的旧记录会显示“无法还原此前经过”，不根据相邻记录或时间推测路线。更新之后的新战局才能保存这些数据，历史物品仍能直接使用折叠显示。

入场装备、带出与保留、新增物品默认按整件展示枪械和防弹衣。安装在父物品上的 `mod_*` 部件、装甲插板、软甲部件和装填弹药归入所属装备，点击“展开部件”查看。背包格子里的独立配件仍单独列出。

新增物品中的新附件若安装在原有枪械上，会显示“原装备的新增部件”；原枪只是分组上下文，不会被算成新增物品。原始物品 ID、父子关系、数量和 JSON 不改变。缺失父节点的旧物品保持可见，循环父子关系不会卡死。

同时修复从详情返回列表时继续绘制已清空详情的异常。历史测试覆盖装备分组、独立配件、嵌套安装、插板、装填弹药、新增附件、缺失／循环父节点、路线重复访问以及生产页面的折叠／展开／路线／返回操作；SQLite 和原有读取回归检查继续通过。

需同时更新客户端和 `LocalGearAdmin.module`，再重启。游戏内视觉验证仍由用户完成。
