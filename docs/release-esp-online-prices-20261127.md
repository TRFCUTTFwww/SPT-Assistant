# 2.4 — ESP 使用联网跳蚤价格（2026-11-27）

此前联网跳蚤已更新价格，但 ESP 的普通物品估值仍只读取随安装附带的 `esp5-prices.json`。现在 ESP 复用服务端 `LocalGearMail/flea-prices` 的价格缓存与设置，跟随现有 PVE、PVP、本地模式及有效的手动定价，无须打开跳蚤面板。

价格优先级：有效手动定价 → 当前模式在线同步缓存 → 本地估值表。比特币继续优先使用原有实时比特币控制的价格。无网时服务端保留上次成功缓存；文件暂时缺失、损坏或为空时客户端保留当前模式最近读到的有效价格；从未缓存过或在线缺失的物品逐项回退本地估值。PVE 与 PVP 缓存独立，切换来源不会混用另一个来源的价格。本地模式不使用在线价，但保留手动定价。

服务端继续使用既有同步机制（成功缓存一小时内不重复抓取，失败按既有重试机制处理，也可在跳蚤面板手动刷新）。客户端每五秒在后台检查文件变动，只在内容版本变化时解析并发布新快照，不在 ESP 绘制时读文件或联网。这不是逐笔成交的实时价格；数值仍取决于上游价格库和最近一次成功同步。

新价格同时用于地面物品、附件和堆叠总价、容器、尸体、本局搜刮列表及每格价值筛选。价格改变时清除容器估值缓存并重新安排本局扫描，高价值判定也随新价格重算。原有物品分类配色保持不变。

验证：19 项自动检查覆盖在线覆盖旧价、部分缺价、连续更新、损坏/空/缺失缓存、模式隔离、断网恢复、手动价设置/取消、本地模式、无效数据以及离线重启。客户端 Release 构建通过（0 错误，5 项既有警告）。安装目录缓存读取验证为 PVE、3,273 项有效价格。

已覆盖安装客户端核心并完成热更新：运行时 SHA-256 与构建产物一致，状态为 `ready=true`、无错误、无回滚；游戏日志确认 `ESP flea prices updated: mode=pve, 3273 prices`。

游戏内视觉检查由用户完成：观察已知价格物品及容器总价；切换跳蚤价格来源或修改某件物品定价后等待约五秒，并检查搜刮排序和价值筛选。服务端无需更换模块。
