# 无限库存下报价暂停状态与解除暂停修复（2026-11-27）

修复开启市场无限库存时，修改窗口把暂停报价读成永久、解除暂停后仍保留永久截止时间的问题。

根因是 SPT 的 `RagfairOffer` 记录复制构造函数没有复制基类的 `ExtensionData`。无限库存生成副本时，暂停秒数、自定义报价和持久化标记随之丢失。之前的回归未覆盖无限库存与暂停报价同时启用；仅验证服务端已下架记录也未能发现此问题。

本次仅在三处报价投影中显式复制扩展数据：无限库存、暂停到期时间、纯卢布转换。副本使用独立字典，避免后续修改影响原始报价。修改窗口继续读取当前报价状态，底部说明小字已删除，保存提示缩短为“报价已保存。”。

验证：

- 新增“无限库存副本保留暂停标记”回归，先复现失败，再验证修复通过；同时检查自定义标记、原生到期投影、纯卢布转换和字典隔离。
- SQLite 双进程回归覆盖无限库存下读取暂停状态、保留或关闭持久化后解除暂停，确保恢复有限倒计时。
- 在当前运行服务端保留原无限库存配置，分别创建临时及持久化测试报价，执行新增暂停报价、读取状态、解除暂停、保存、再次读取、删除的完整接口流程。两种模式均正确返回暂停 1020 秒，解除后为非暂停、非永久，实际剩余 1019 秒。测试报价已全部清理。
- 客户端 Release 构建、服务端管理模块构建和本地化检查通过；客户端及服务端运行哈希与本次构建一致，旧模块备份位于 `mod-backups/flea-pause-metadata-20261127-115426`。

旧逻辑已经保存为永久、且未持久化原冻结秒数的临时报价无法自动推断原时长。需取得原剩余分钟后才能恢复该现有报价。游戏内画面由用户检查。
