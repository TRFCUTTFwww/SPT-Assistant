# CP2077 Quickhacks 独立原型 0.4.0

目标：SPT 5.0 / EFT 48558，BepInEx IL2CPP / .NET 10。插件名称 CP2077 Quickhacks，配置文件 `BepInEx/config/local.cp2077.quickhacks.cfg`。独立于 SPT Assistant，可与其及其内置黑墙脉冲共存。

本版用于检查扫描界面、上传与施放、门禁入侵交互。采用本地 2077 图标、WAV 和黑墙图集，Unity 重建界面及目标特效。尚未做到原版字体、全部转场、人物动画或材质的一比一复刻。

0.3.1 按本机 `D:/aaa` 两张 1920×1080 参考图重排入侵协议：紫黑半透明底、全屏细框及边缘技术纹样、左上 NETTECH 与线框地球、顶部长条、左侧紧凑 7×7 代码矩阵、右上八格缓冲，以及右侧三行程序。0.3.3 将右侧三行改为独立的网络诊断、访问映射和门禁授权序列，分别匹配；辅助目标不产生物品或数据挖掘奖励。结束时左侧替换为绿色或红色终端日志、结果板和退出按钮，保留至手动退出，计时冻结。图中视频水印和 FPS 不属于界面。

扫描器保留左侧快速破解、中央光学取景、右侧目标数据和上方 RAM 栏；接入原版扫描刻度、内存格、选中底板和技术纹样。无真实目标的 F10 预览使用光学人体轮廓，战局中的锁定框按目标投影尺寸调整。

0.3.2 增加入侵协议动画：开场边框展开、扫描线掠过、标题条展开及矩阵代码逐行解码；悬停边框呼吸、选码闪烁、代码沿弧线飞入缓冲区，落位后才显示缓冲代码；匹配序列闪亮并显示下一代码提示。最后一次选码飞入后，矩阵以短暂故障条纹切换为终端；终端展开、日志逐字输出、封包点线和完成状态推进、程序结果依次展开，最后展开结果板与退出按钮。约三秒后播放一次完成音效。失败采用红色终端及拒绝结果。所有动画使用非缩放时间，支持不同帧率；选码飞行不锁住下一次合法选择，开场代码全部稳定后才接受输入，ESC 随时可退出。

动画仅控制显示和音效时序；结算时若门禁授权序列已匹配，由原有单次授权逻辑提交开门，不因动画重复提交授权。

已有入侵协议图标（DoorAuthorization）和打开、关闭、选码、成功、失败等音效，可用于上传魔偶界面；代码矩阵与交互由插件重建。当前黑墙上传提示临时使用资源包中的突触熔融音效，黑墙死亡音效使用补充包原素材。

0.3.4 降低入侵难度：每条独立序列固定三个代码，缓冲区十格、时间六十秒。缓冲字符缩小两像素并上移三像素，落位和飞入动画共用字符对齐，缓冲外框按十格扩展。


0.4.0 加入完整七项列表：重启义眼、武器故障、阻碍移动、记忆清除、请求支援、赛博精神病、黑墙网关。全部接入本地原版独立图标和对应音效（黑墙上传仍为前述临时音效）。左侧紧凑七行，选中扫光、依次出现动画，右侧显示类别、说明与持续时间。

上传时在真实目标头顶绘制跟随视角的原版技能图标、分段旋转环、进度条和百分比；生效后显示剩余时长与状态环，可同时显示不同效果。义眼加入横向故障线，精神病加入旋转外环，黑墙加入红色碎片；同时保留目标身上的短暂故障图块和黑墙图集动画。头顶标记受距离、相机前后和墙体遮挡限制，目标离场或效果结束自动清理；非扫描状态也保留可见目标标记。F10 人体预览也包含上传到生效的头顶反馈。上述界面、状态环和特效由 Unity 重建，尚非原生 REDengine 字体、材质和动画的逐帧复制。

扫描默认改为左 Ctrl，需单独按住约 0.25 秒；其他按键组合优先，直到松开 Ctrl 才重新允许扫描。扫描期间 F 上传、滚轮选择、鼠标点击仍有效；ESC 关闭后不会因 Ctrl 仍按住而重开。背包或其他有光标的界面不触发。Ctrl + F8 热更新保留。此策略不能使 Ctrl 变成空闲键：本机 Skipper 已使用左 Ctrl，FIKA 右 Ctrl 为聊天，其他 Mod 独立读取键盘的行为仍可能同时发生；可在配置改回 F9。没有改写 EFT 或其他插件的键位。

## 操作

- **F10**：界面与无伤施放预览，可在主菜单打开。选择七种技能，点击「执行施放模拟」或按 F；点击右侧「入侵协议 · 门禁授权」检查代码矩阵。预览不选择或伤害 AI，不操作任何门。施放模拟启动后保留当次技能，即使切换列表选项也不会改变已开始的模拟。
- **单独按住左 Ctrl 约 0.25 秒**：战局内扫描 AI，滚轮或鼠标选技能，**F** 上传。松开左 Ctrl 返回游戏。上传结束前目标离开视线、范围、战局，或玩家死亡、失焦会取消。
- **ESC**：取消当前界面或尚未完成的门禁破解。关闭后恢复原光标状态；不修改时间倍率。
- 热键、扫描范围、音量可在 BepInEx 配置修改；默认不占用原有黑墙 F11。

## 门卡与破解共存

原生 CardReader / KeycardDoor 的门卡选项列表末尾增加独立的 **「破解」**。原有实体卡选项和原有选中项保留；万能门禁卡功能也可继续提供自己的选项。没有实体卡时也可选择破解。只有点击「破解」才进入入侵协议，不会自动拦截刷卡，不创建门卡物品，不改门的 KeyId 或卡片次数。

小游戏从首行开始，随后交替在所在列、所在行选码；同格不可重复，矩阵为 7×7，缓冲区为 10。首个有效选择后开始 60 秒计时。三条魔偶序列独立匹配，每条长度为 3，顺序随每局变化，不是同一序列的逐级前缀。生成器确保存在利用重叠用七步完成全部序列，留出三格余量的合法路径。匹配一条后继续选码；全部完成、缓冲区用尽、无可选格或计时结束时结算。结算时已匹配「门禁授权」才提交一次开门；辅助目标成功不能单独开门。取消、离开 4 米交互距离、死亡或战局切换均不授权。

鼠标悬停高亮代码，点击选码。也可用方向键在当前可选行或列中循环选择，F / Enter 确认；静止鼠标不会抢回键盘焦点。底部操作提示栏已移除，快捷键保留：H 显示规则，C / ESC 关闭；完成后点击「退出界面」。F10 内的入侵预览退出后返回扫描预览。成功授权改变门锁状态后仍可查看结果。

CardReader 按原 `_keyMap` 中唯一的成功触发器向当前战局 `TriggersEmitter` 发出授权，播放原生成功提示；多个不同成功出口的特殊刷卡器会拒绝自动选择。KeycardDoor 调用原生 Unlock。入口依赖原生门禁交互分派，不提供未供电门禁的独立绕过入口。不同地图的供电、门禁、剧情及一次性触发仍需实机逐项验证。

## AI 效果

- 重启义眼：10 秒内抑制视觉检测，清除当前视觉追踪，不暂停 AI 移动或听觉。
- 赛博精神病：20 秒内将附近 AI 作为敌对目标，包含同队 AI；临时覆盖敌我判定并驱动原生敌人记忆，不合并或改写原队伍。结束时移除本插件添加的个人敌人记忆，恢复其原有目标与攻击设置。复杂首领或第三方 AI 的同队开火仍待战局验证。
- 黑墙网关：上传后施加原生玩家来源伤害，确认死亡后才继续向 8 米内、无遮挡、未访问的 AI 传播，最多 5 个。不会选择人类玩家；不绕过辅助 Mod 的显式 AI 无敌保护。目标使用黑墙图集碎片，音画为 Unity 重建。
- 武器故障：10 秒内阻止目标扣动扳机与通过开火检查，仍允许观察、移动及换弹；不永久损坏武器或修改物品耐久。
- 阻碍移动：10 秒内锁住原生移动器 Pause，不暂停 AI 思考、视线或射击；结束、失焦或热更新时恢复此前 Pause 状态。外部 Mod 已接管的暂停值不覆盖。
- 记忆清除：移除个人战斗目标及敌人记忆，8 秒内阻断视觉重新锁定并清理重新写入的战斗记忆；不删除队伍的敌对关系，结束后可重新发现敌人。与同一目标的赛博精神病互相替换。
- 请求支援：向 40 米内最近的空闲同队 AI 提交原生 GoToPointRequest，让它前往被破解目标的上传完成位置。仅选择没有战斗目标、没有当前请求、未被本插件锁住移动或发狂的队友，最长 15 秒；不生成新 AI，不修改阵营。不具备队伍控制器、无人可响应或重复呼叫会提示失败并返还 RAM。请求是否被特殊首领或第三方 AI 执行仍需实机验证。
- 原型 RAM 上限 24，每秒恢复 1；按列表顺序，七种技能消耗为 2、3、4、6、4、8、12，上传时间为 1.5、1.5、1.5、2、1、3、4 秒。这是 EFT 适配数值，不是 2077 各阶级数值的完整复刻。

当前仅面向单机或本机实际拥有 AI 控制权的战局；尚未实现 FIKA 客户端请求与同步。

## 构建和安装

0.3.0 使用独立常驻加载器和可替换逻辑模块，不依赖 SPT Assistant 的宿主。配置文件和插件 GUID 保留。

- 默认自动检测 `runtime/Local.Cp2077.Quickhacks.Core.module` 更新；文件稳定约半秒后切换。**Ctrl + F8** 手动重载逻辑和图片、音效缓存，可在配置中更改热键或关闭自动检测。
- 进行中的 AI 上传或门禁小游戏结束、取消后才切换；重载会关闭扫描界面、释放旧临时 AI 效果及音画对象，恢复输入，重新绑定补丁并加载新逻辑。旧门禁回调在退出该代逻辑后立即失效。
- 损坏或接口不兼容的模块在停止旧版本之前被拒绝；新版初始化失败时清理候选并尝试恢复上一版。`runtime/hotreload-status.json` 记录当前逻辑版本、代数和错误。
- 模块从内存加载，不锁住磁盘上的 `.module`。基于 IL2CPP/Harmony 的原生跳板要求，旧程序集元数据保留到客户端退出；每代的补丁、委托入口与 Unity 对象会清理。加载器本身变化仍需要重启。
- 首次从 0.1 / 0.2 迁移需要重启一次。若客户端正在运行，安装器会验证并排队完整安装包，启动隐藏安装进程等待这个客户端退出，再备份并安装；不会关闭游戏。安装状态见 `mod-updates/quickhacks-install-status.json`。之后使用同一加载器的更新可以在运行中安装。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build-Quickhacks.ps1 -GameRoot 'D:\SPT-5.0.0-48558' -ResourceRoot 'D:\CP2077_Quickhack_Resources_20261112' -BlackwallRoot 'D:\CP2077_Blackwall_Supplement_20261112' -Dotnet 'D:\SPT_Mod_Staging_20261027\dotnet-sdk\dotnet.exe' -HostReleaseRevision '3c728b5b0e7b5c8665597048f5c947e295b7ae23' -OutputDirectory 'D:\SPT_Mod_Staging_20261027\quickhacks-0.4.0' -Install
```

脚本构建加载器与逻辑模块，运行离线检查，按本地资源清单逐项验证 SHA256 后打包。输出目录须为空；`-Install` 调用安装器，备份已有独立插件，先复制资源，再原子发布逻辑模块。分发包也可运行 Install.ps1 并指定 GameRoot。资源只保留在本地安装包，不提交源码仓库。

`HostReleaseRevision` 用于复现已发布加载器的 Git 信息版本，避免仅因仓库新增提交而将同一加载器误判为需要重启的更新；上例对应本机 0.3.0 加载器。此参数仅用于加载器构建，逻辑模块保留本次构建元数据；加载器源码有实际变化时，其 SHA256 仍会变化，安装器仍要求重启。

卸载：关闭客户端后移走 `BepInEx/plugins/CP2077Quickhacks`。配置可保留。没有服务端、存档或物品模板修改。

## 验证边界

编译、离线解码、谜题求解与 API 检查不等于游戏内画面、声音或门禁已经通过验收。游戏界面检查由用户完成：先在主菜单 F10 预览；进入战局确认真实卡列表保留，再分别检查取消、失败和成功开门；最后对少量 AI 检查七种效果。
